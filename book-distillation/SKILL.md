# 书籍蒸馏 Skill

## 概述

将专业书籍转化为 Agent Skill 的系统化流程，保留核心知识、淘汰冗余内容、设计触发条件。

---

## 触发条件

### ✅ 应该使用此 Skill

- 用户想把某本书转化为可复用知识
- 书籍内容是方法论/技术/最佳实践类
- 需要系统性提取而非零散笔记
- 书籍有明确的章节结构和专业深度

### ❌ 不适用场景

- 小说/散文等文学类书籍
- 简单的参考手册（直接查阅即可）
- 已有成熟 Skill 覆盖的领域
- 书籍内容过于宽泛/浅显

---

## 六阶段 SOP

### 阶段0：整书理解（必做）

**目标**：建立全局认知，判断书籍类型

**步骤**：
1. 读取目录，提取章节结构
2. 阅读前言/序言，理解作者意图
3. 扫描每章开头/结尾，识别核心内容
4. 分类书籍类型（见下表）

**书籍类型与策略**：

| 类型 | 特征 | 蒸馏重点 | Agent数量 |
|------|------|----------|-----------|
| **方法论导向** | 技术手册、实验方法、最佳实践 | 可复现方法、工具清单、评估标准 | 3-4 |
| **概念导向** | 教科书、理论基础 | 核心概念、思维框架、知识图谱 | 2-3 |
| **参考导向** | 编码手册、API文档 | 快速查找表、代码模板、常见问题 | 1-2 |
| **案例导向** | 案例集、实战指南 | 通用模式、反模式、决策树 | 2-3 |

**输出**：`00-book-overview.md`（目录+类型判断+初步策略）

---

### 阶段1：并行提取（必做）

**目标**：多维度提取，避免遗漏

**原则**：
- Agent 数量 = 提取维度数量
- 维度由书籍类型决定（见上表）
- 每个 Agent 独立输出，互不干扰

**Agent 角色设计模板**：

```
方法论导向书（推荐4 Agent）：
- Agent 1: 方法/算法提取
- Agent 2: 工具/资源整合  
- Agent 3: 评估/基准体系
- Agent 4: 局限性/补充点

概念导向书（推荐3 Agent）：
- Agent 1: 核心概念定义
- Agent 2: 概念关系图谱
- Agent 3: 应用场景映射

参考导向书（推荐2 Agent）：
- Agent 1: 快速查找表
- Agent 2: 常见问题/陷阱

案例导向书（推荐3 Agent）：
- Agent 1: 成功模式提取
- Agent 2: 反模式总结
- Agent 3: 决策点识别
```

**Agent Prompt 模板**：

```markdown
Read the book [BOOK_PATH] and extract [TASK].

Focus on:
1. [Focus point 1]
2. [Focus point 2]
3. [Focus point 3]

Output format:
- Use markdown
- Include specific chapter/page references
- Group related items
- Note any cross-references to other chapters

Save output to: [OUTPUT_FILE]
```

**输出**：`XX-extraction.md`（每个 Agent 一个文件）

---

### 阶段2：三重验证筛选（必做）

**目标**：淘汰低价值内容，保留可复用知识

**三重验证标准**：

| 验证类型 | 说明 | 通过条件 |
|----------|------|----------|
| **跨域验证** | 该知识在书中多个场景出现 | ≥2处独立引用 |
| **预测力测试** | 能否推导书中未直接讨论的问题 | 可扩展应用 |
| **独特性检验** | 是否为专业见解，非常识 | 需专业知识才能得出 |

**执行步骤**：
1. 读取所有提取文件
2. 逐项应用三重验证
3. 标记：✅ 通过 / ⚠️ 部分通过 / ❌ 淘汰
4. 统计淘汰率（健康范围：40-70%）

**淘汰原则**：
- 常识性内容（"蛋白质很重要"）
- 单章节孤立内容（除非价值极高）
- 无扩展潜力的细节
- 已有更好资源的内容

**输出**：`validation-results.md`（验证结果+淘汰统计）

---

### 阶段3：Skill构造（必做）

**目标**：设计触发条件和知识结构

**核心设计要素**：

#### 1. 触发条件
```
应该触发：
- [场景1关键词]
- [场景2关键词]
- ...

不应该触发：
- [场景A]（原因是...）
- [场景B]（原因是...）
```

#### 2. 核心内容结构
```markdown
## 核心方法/概念
[通过验证的内容，按逻辑分组]

## 快速参考
[速查表：公式、定义、决策树]

## 工具/资源清单
[分类整理，标注可用性]

## 脚本/代码示例
[可直接使用的代码]
```

#### 3. 用户交互设计
| 用户问题类型 | Skill 响应模式 |
|-------------|---------------|
| 方法选择 | 推荐+理由+工具 |
| 工具使用 | 脚本示例+参数 |
| 结果解读 | 指标解释+标准 |
| 对比决策 | 对比表+建议 |

**输出**：`SKILL.md`（主文件）+ `references/`（详细参考）

---

### 阶段4：关系链接（可选）

**何时跳过**：阶段3已明确依赖/对比关系

**何时执行**：
- Skill 较复杂，有多个外部依赖
- 需要与其他 Skill 协同工作
- 用户明确要求

**关系类型**：
- **依赖**：本 Skill 需要其他 Skill 支持
- **对比**：本 Skill 与其他 Skill 的区别
- **组合**：本 Skill 与其他 Skill 的协作链

**输出**：`skill-relationships.md`

---

### 阶段5：压力测试（可选）

**何时跳过**：实际使用中自然验证更高效

**何时执行**：
- Skill 是核心基础设施
- 错误触发代价高
- 用户明确要求

**测试类型**：
1. **正向测试**：应该触发的场景
2. **负向测试**：不应该触发的场景（诱饵测试）
3. **边界测试**：模糊场景的判断

**输出**：`test-cases.md`

## 实战经验与优化

### Agent 数量优化

**原则**：宁少勿多，每个 Agent 有明确独特价值

```
判断标准：
- 提取维度是否有重叠？
- 合并后是否会遗漏？
- 用户真正需要几个视角？

常见错误：
❌ 套用通用模板（5 Agent 无论什么书）
❌ 过度细分（Agent 提取内容高度重叠）
✅ 根据书籍类型定制
```

### 跳过阶段判断

| 情况 | 跳过阶段 | 原因 |
|------|----------|------|
| 书籍简单、提取内容少 | 阶段4-5 | 投入产出比低 |
| 阶段3已包含关系设计 | 阶段4 | 重复工作 |
| 迭代式优化 | 阶段5 | 实践中验证更真实 |
| 核心基础设施 Skill | 不跳过 | 质量要求高 |

### 淘汰率解读

| 淘汰率 | 含义 | 建议 |
|--------|------|------|
| <30% | 验证太宽松 | 提高标准 |
| 40-70% | 健康 | 正常 |
| >80% | 验证太严或书价值低 | 检查标准/考虑放弃 |

### 常见陷阱

1. **舍不得删**：什么都想保留 → Skill 臃肿无用
2. **跳过验证**：直接进入构造 → 保留低价值内容
3. **触发太宽**：什么场景都触发 → 用户困惑
4. **忽略常识判断**：把常识当专业知识 → Skill 无价值

## 使用示例

### 输入
```
用户：把《Protein Supersecondary Structures》这本书蒸馏成 Skill
```

### 执行流程
```
1. 阶段0：识别为"方法论导向"技术书 → 4 Agent 方案
2. 阶段1：spawn 4 Agent（方法/工具/评估/AI补充）
3. 阶段2：三重验证，淘汰率 50-65%
4. 阶段3：设计触发条件 + 核心方法 + 脚本
5. 阶段4-5：跳过（投入产出比不高）
```

### 输出
```
~/.openclaw/skills/protein-sss/
├── SKILL.md
├── references/
└── scripts/
```
